# MaxBot

SaaS-сервис для мессенджера [MAX](https://max.ru). Автоматически дублирует посты из канала в группу обсуждений, управляет верификацией новых участников и публикует отложенные посты.

## Возможности

### Канал → группа
- **Автодублирование постов** — бот отслеживает новые публикации в канале и пересылает их в группу обсуждений с заголовком-ссылкой на источник
- **Кнопка комментариев** — к каждому посту в канале прикрепляется inline-кнопка «💬 Прокомментировать», ведущая напрямую к обсуждению в группе

### Верификация участников (captcha-gate)
- **Встроенный механизм** — при вступлении нового участника бот автоматически отправляет сообщение-приветствие с кнопкой подтверждения и deep-link'ом
- **Ограничение до верификации** — сообщения неверифицированного участника мгновенно удаляются, пока он не нажмёт кнопку
- **Кик по таймауту** — если пользователь не прошёл проверку за отведённое время (по умолчанию 10 мин), планировщик исключает его из группы
- **Приветственный DM** — после верификации бот отправляет пользователю личное сообщение с кнопкой возврата в чат
- **Гибкие шаблоны** — тексты сообщений и кнопок настраиваются; поддерживаются плейсхолдеры `{имя}`, `{группа}`, `{минут}`
- **Два режима конфигурации:**
  - *Пары канал → группа* — верификация как часть существующей пары
  - *Самостоятельные конфиги* (WelcomeConfig) — верификация для любой группы без привязки к каналу

### Публикация
- **Автопостинг** — планировщик публикует отложенные посты в заданное время; поддерживается Markdown и вложения
- **Очередь постов** — статусы `pending → sent / failed` с сохранением текста ошибки

### Управление
- **Несколько ботов** — каждый пользователь добавляет несколько ботов MAX и назначает их на разные пары или конфиги верификации
- **Веб-интерфейс** — полный CRUD для ботов, пар, конфигов верификации и расписания через браузер
- **Журнал событий** — лог всех действий (info / warning / error) с привязкой к боту и пользователю

## Стек

| Компонент     | Технология                                      |
|---------------|-------------------------------------------------|
| Web UI + API  | FastAPI, Jinja2, Tailwind CSS                   |
| База данных   | PostgreSQL 16 + SQLAlchemy (async) + Alembic    |
| Бот           | HTTP long-polling (или webhook), MAX Bot API    |
| Планировщик   | APScheduler (публикация + кик по таймауту)      |
| Упаковка      | Docker Compose (5 сервисов)                     |
| Безопасность  | JWT (cookie), Fernet-шифрование токенов ботов  |

## Быстрый старт

### Требования

- Docker и Docker Compose

### Запуск

```bash
git clone https://github.com/ProKoKos/maxbot.git
cd maxbot
cp .env.example .env
```

Отредактируйте `.env` — минимально необходимые значения:

```env
SECRET_KEY=<случайная строка 32+ символа>
ENCRYPTION_KEY=<Fernet-ключ, см. ниже>
ADMIN_EMAIL=you@example.com
ADMIN_PASSWORD=yourpassword
POSTGRES_PASSWORD=yourdbpassword
```

Сгенерировать `ENCRYPTION_KEY`:
```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Запустить:
```bash
make up
# или вручную:
docker compose up --build -d
```

Откройте [http://localhost:8000](http://localhost:8000) и войдите с данными из `.env`.

## Настройка

### 1. Добавить бота

Перейдите в раздел **Боты** → **+ Добавить бота**. Введите токен бота MAX (получить у [@MaxBot](https://max.ru/maxbot)). Токен проверяется через MAX API и сохраняется в зашифрованном виде.

> Бот должен быть **администратором** в канале и **участником** группы обсуждений.

### 2. Создать пару канал → группа

Перейдите в раздел **Пары** → **+ Добавить пару**. Выберите бота — каналы и группы, в которых он состоит, загрузятся автоматически из API. Ссылка на группу для кнопки комментариев подставляется из имеющихся данных автоматически; при необходимости её можно задать вручную в настройках пары.

После сохранения бот начнёт дублировать новые посты из канала в группу и добавлять кнопку «💬 Прокомментировать».

### 3. Настроить верификацию участников

**Вариант А — в рамках пары:** в настройках пары включите «Верификация» и задайте параметры (таймаут, текст сообщения, поведение при истечении).

**Вариант Б — самостоятельный конфиг:** перейдите в раздел **Верификация** → **+ Добавить группу**. Выберите бота и группу; бот начнёт встречать новых участников независимо от наличия связанного канала.

При вступлении нового пользователя:
1. Бот отправляет в группу сообщение с deep-link кнопкой
2. Сообщения пользователя автоматически удаляются до нажатия кнопки
3. Пользователь переходит в бота, нажимает «Я не бот» → верификация пройдена
4. Бот удаляет сообщение из группы и отправляет приветственный DM с кнопкой возврата
5. Если таймаут истёк, планировщик исключает пользователя из группы (если включён кик)

### 4. Автопостинг

В разделе **Автопостинг** создайте отложенный пост: выберите пару, напишите текст (поддерживается Markdown) и укажите время публикации. Планировщик проверяет очередь каждые 30 секунд.

## Переменные окружения

| Переменная          | Описание                                         | Обязательно    |
|---------------------|--------------------------------------------------|----------------|
| `SECRET_KEY`        | Ключ подписи JWT                                 | ✅             |
| `ENCRYPTION_KEY`    | Fernet-ключ для шифрования токенов ботов         | ✅             |
| `ADMIN_EMAIL`       | Email первого пользователя (создаётся при старте)| ✅             |
| `ADMIN_PASSWORD`    | Пароль первого пользователя                      | ✅             |
| `POSTGRES_PASSWORD` | Пароль базы данных                               | ✅             |
| `BOT_MODE`          | `polling` (по умолчанию) или `webhook`           | —              |
| `WEBHOOK_URL`       | URL для webhook-режима                           | только webhook |
| `WEBHOOK_SECRET`    | Секрет для проверки webhook-запросов             | только webhook |

```

├── bot/
│   ├── main.py        # Точка входа; polling или webhook режим

│   ├── handlers.py    # Обработчики событий MAX API
│   ├── client.py      # Async-клиент MAX Bot API (httpx)
│   ├── buttons.py     # Сборщики inline-кнопок и заголовков
│   └── crypto.py      # Fernet-шифрование/дешифрование токенов
├── db/
│   ├── models.py      # SQLAlchemy ORM-модели
│   ├── session.py     # AsyncSessionLocal + engine
│   └── alembic/       # Миграции (001…005)
├── scheduler/
│   └── main.py        # APScheduler: автопостинг + кик по таймауту
├── shared/
│   └── config.py      # Pydantic-настройки (env vars)
├── web/
│   ├── main.py        # FastAPI app; сидирование admin-пользователя
│   ├── auth.py        # JWT + bcrypt
│   ├── deps.py        # DI: CurrentUser, DBSession, RateLimit
│   ├── routers/
│   │   ├── api.py     # REST API (/api/*)
│   │   └── pages.py   # HTML-страницы (Jinja2)
│   ├── templates/     # HTML-шаблоны
│   └── static/        # CSS, JS
└── docker-compose.yml
```

## Модели базы данных

| Модель                | Назначение                                              |
|-----------------------|---------------------------------------------------------|
| `User`                | Пользователь сервиса                                    |
| `Subscription`        | Тарифный план и лимиты                                  |
| `Bot`                 | Бот MAX; токен хранится в зашифрованном виде            |
| `ChannelGroupPair`    | Пара канал → группа + настройки верификации             |
| `WelcomeConfig`       | Самостоятельный конфиг верификации для любой группы     |
| `VerificationRequest` | Запрос верификации конкретного участника (pending → verified / kicked / expired) |
| `ScheduledPost`       | Отложенный пост (pending → sent / failed)               |
| `PostLink`            | Маппинг ID поста в канале → ID сообщения в группе       |
| `PollingMarker`       | Курсор long-polling (сохраняется между перезапусками)   |
| `EventLog`            | Журнал событий с уровнями info / warning / error        |
