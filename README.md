# MaxBot

SaaS-сервис для мессенджера [MAX](https://max.ru). Автоматически дублирует посты из канала в группу обсуждений и добавляет к каждому посту кнопку «💬 Прокомментировать».

## Возможности

- **Автодублирование постов** — бот отслеживает новые публикации в канале и пересылает их в группу обсуждений с заголовком-ссылкой на канал
- **Кнопка комментариев** — к каждому посту в канале прикрепляется inline-кнопка, ведущая напрямую к обсуждению в группе
- **Несколько ботов** — каждый пользователь может добавить несколько ботов MAX и назначить их на разные пары канал → группа
- **Автопостинг** — планировщик публикует посты в заданное время с учётом часового пояса браузера
- **Веб-интерфейс** — управление ботами, парами и расписанием через браузер
- **Журнал событий** — лог всех действий с фильтром по уровню

## Стек

| Компонент | Технология |
|-----------|-----------|
| Web UI + API | FastAPI, Jinja2, Tailwind CSS |
| База данных | PostgreSQL 16 + SQLAlchemy (async) + Alembic |
| Бот | HTTP long-polling, MAX Bot API |
| Планировщик | APScheduler |
| Упаковка | Docker Compose (4 сервиса) |
| Безопасность | JWT, Fernet-шифрование токенов ботов |

## Быстрый старт

### Требования

- Docker и Docker Compose

### Запуск

```bash
git clone https://github.com/ProKoKos/maxbot.git
cd maxbot
cp .env.example .env
```

Отредактируйте `.env` — минимально необходимые значения:

```env
SECRET_KEY=<случайная строка 32+ символа>
ENCRYPTION_KEY=<Fernet-ключ, см. ниже>
ADMIN_EMAIL=you@example.com
ADMIN_PASSWORD=yourpassword
POSTGRES_PASSWORD=yourdbpassword
```

Сгенерировать `ENCRYPTION_KEY`:
```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Запустить:
```bash
make up
# или вручную:
docker compose up --build -d
```

Откройте [http://localhost:8000](http://localhost:8000) и войдите с данными из `.env`.

## Настройка

### 1. Добавить бота

Перейдите в раздел **Боты** → **+ Добавить бота**. Введите токен бота MAX (получить у [@MaxBot](https://max.ru/maxbot)). Токен проверяется и сохраняется в зашифрованном виде.

### 2. Создать пару канал → группа

Перейдите в раздел **Пары** → **+ Добавить пару**. Выберите бота — каналы и группы, в которых он состоит, загрузятся автоматически из API. Укажите ссылку на группу для кнопки комментариев (для публичных групп заполняется автоматически).

> Бот должен быть **администратором** в канале и **участником** группы обсуждений.

### 3. Проверить работу

Опубликуйте пост в канале. Бот дублирует его в группу и добавит кнопку «💬 Прокомментировать» к посту в канале.

## Автопостинг

В разделе **Автопостинг** создайте отложенный пост: выберите пару, напишите текст (поддерживается Markdown) и укажите время публикации в вашем часовом поясе. Планировщик проверяет очередь каждые 30 секунд.

## Переменные окружения

| Переменная | Описание | Обязательно |
|---|---|---|
| `SECRET_KEY` | Ключ подписи JWT | ✅ |
| `ENCRYPTION_KEY` | Fernet-ключ для шифрования токенов ботов | ✅ |
| `ADMIN_EMAIL` | Email первого пользователя (создаётся при старте) | ✅ |
| `ADMIN_PASSWORD` | Пароль первого пользователя | ✅ |
| `POSTGRES_PASSWORD` | Пароль базы данных | ✅ |
| `BOT_MODE` | `polling` (по умолчанию) или `webhook` | — |
| `WEBHOOK_URL` | URL для webhook-режима | только webhook |
| `WEBHOOK_SECRET` | Секрет для проверки webhook-запросов | только webhook |

## Make-команды

```bash
make up              # собрать и запустить все сервисы
make down            # остановить
make build           # пересобрать образы без кеша
make logs            # логи всех сервисов
make logs-bot        # логи бота
make logs-scheduler  # логи планировщика
make migrate         # применить миграции вручную
make migrate-create  # создать новую миграцию
make shell-web       # bash внутри web-контейнера
make shell-db        # psql
make ps              # статус контейнеров
```

## Структура проекта

```
├── web/            # FastAPI: REST API + Jinja2 UI
│   ├── routers/    # api.py (JSON), pages.py (HTML)
│   ├── templates/  # HTML-шаблоны
│   └── static/     # CSS
└── docker-compose.yml
```
